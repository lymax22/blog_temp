# Git 最短工作流博客设计

## 目标

将现有的 `source/_posts/git-cmd.md` 扩写为一篇面向科研代码项目的中文入门文章。读者完成文章中的最短闭环后，能够初始化仓库、排除不应追踪的文件、完成一次有意义的提交，并安全地推送到已配置的远程仓库。

## 读者与范围

文章面向已有代码或仿真项目、但尚未形成 Git 习惯的科研读者。示例使用通用的 `scp-simulation` 项目名，避免依赖某个真实仓库。

本文涵盖：仓库初始化、`.gitignore`、暂存与提交、分支、推送前检查，以及标签的用途。

本文不涵盖：SSH 密钥创建、代理配置、令牌认证、远程分支合并与历史冲突恢复。这些主题仅在结尾列为后续文章，避免把首篇文章变成环境排障手册。

## 内容结构

1. 说明 Git 对可复现实验的价值：提交连接代码、参数和结果解释，而不是替代数据备份。
2. 用一个项目目录演示 `git init`、首次提交和远程推送的最短命令序列。
3. 展示适用于 Python、MATLAB 与 LaTeX 的 `.gitignore` 示例，并说明密钥和大结果文件不应提交。
4. 给出日常实验的轻量规则：一次实验意图对应一次提交；新尝试使用分支；可复现实验版本使用标签。
5. 以推送前检查单收束，并链接未来的 SSH、远程协作和网络排障文章。

## 写作与安全约束

- 使用中文、短段落和可直接复制的代码块。
- 所有仓库地址、用户名和分支名使用明确占位符。
- 不展示任何令牌、真实代理端口、私钥路径或破坏性系统命令。
- 保留现有文章日期和 `git` 标签；新增 `科研工作流` 标签与 `科研工程` 分类。

## 验证

使用 Hexo 生成到临时目录，验证文章能渲染，并检查生成页面包含标题、核心章节和代码块；不得改写当前工作区的 `public/`。
